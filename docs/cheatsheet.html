Anatomy of a SELECT Parts 1–4

Write the clauses in this order. The circle shows the order the database actually runs them.

SELECTwhich columns to show5
FROMwhich table (+ JOINs)1
WHEREkeep matching rows2
GROUP BYbundle rows into groups3
HAVINGkeep matching groups4
ORDER BYsort the result6
LIMITkeep the first N7

Why it matters: WHERE runs before SELECT, so it can't use an alias you made with AS. ORDER BY runs after, so it can.

SELECT name, power_level AS power
FROM characters
WHERE planet_id = 1
ORDER BY power DESC
LIMIT 3;

The NULL trap 2.7

Returns nothing 
WHERE race_id = NULL
Finds Frieza 
WHERE race_id IS NULL

NULL means unknown, so NULL = NULL isn't true. Always use IS NULL / IS NOT NULL. Aggregates like AVG skip NULLs.

Summarizing Part 4

COUNT(*)number of rows
SUM(col)total
AVG(col)average (wrap in ROUND())
MIN(col) / MAX(col)smallest / biggest
 
SELECT planet_id, COUNT(*) AS fighters
FROM characters
WHERE power_level > 1000   -- filters ROWS
GROUP BY planet_id
HAVING COUNT(*) >= 2;      -- filters GROUPS
RuleEvery SELECT column must be in GROUP BY or inside an aggregate.

JOIN vs LEFT JOIN Part 5

SELECT c.name, r.name AS race
FROM characters c
LEFT JOIN races r ON c.race_id = r.id;

ON says how rows match. c and r are short names (aliases) for the tables.

JOIN: only matches
GokuSaiyan
PiccoloNamekian
Frieza—
LEFT JOIN: all from left
GokuSaiyan
PiccoloNamekian
FriezaNULL

Find rows with no match: LEFT JOIN, then WHERE right.id IS NULL. That's how 5.4 finds the empty planet.

Subquery Part 6

A query inside a query. The inner one runs first.

SELECT name, power_level
FROM characters
WHERE power_level >
  (SELECT AVG(power_level) FROM characters);

Changing data Part 7

INSERT INTO characters (name, power_level, planet_id, race_id)
VALUES ('Yamcha', 400, 1, 2)
RETURNING id;

UPDATE characters
SET power_level = 1200
WHERE name = 'Yamcha';

DELETE FROM characters
WHERE name = 'Yamcha';
⚠No WHERE = every row. DELETE FROM characters; empties the table. Run the WHERE as a SELECT first to see what you'd hit.

Foreign keys say no: you can't delete Goku while techniques point at him, or insert a character on planet 99.

Transactions Part 8

All or nothing. Nothing is saved until COMMIT. ROLLBACK undoes everything since BEGIN.

BEGIN;
DELETE FROM techniques WHERE character_id = 1;
DELETE FROM characters WHERE id = 1;
ROLLBACK;   -- or COMMIT; to keep it
TipAbout to run something risky by hand? Wrap it in BEGIN … ROLLBACK first.

Common errors

column "goku" does not existText needs single quotes: 'Goku'
must appear in the GROUP BY clauseAdd the column to GROUP BY, or wrap it in an aggregate
column reference "name" is ambiguousBoth tables have it. Prefix it: c.name
violates foreign key constraintThe id you point at doesn't exist, or something still points at this row
aggregate functions are not allowed in WHEREUse HAVING for conditions on COUNT(), AVG(), …
