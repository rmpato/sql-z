Meet the database

Four tables. Each row has an id, and tables point at each other using those ids.

planets where they live

  • idnumber, auto
  • nametext, unique
  • gravitydecimal
1 Earth · 2 Namek · 3 Vegeta · 4 Other World

races what they are

  • idnumber, auto
  • nametext, unique
1 Saiyan · 2 Human · 3 Namekian · 4 Android

characters the fighters

  • idnumber, auto
  • nametext
  • power_levelnumber
  • planet_id→ planets.id
  • race_id→ races.id
Goku, Vegeta, Gohan, Krillin, Piccolo, Tien, Android 18, Frieza

techniques their moves

  • idnumber, auto
  • nametext
  • character_id→ characters.id
Kamehameha → Goku · Final Flash → Vegeta · …
Primary keyA column that uniquely identifies each row. Here it's always id.
Foreign keyA column that points at another table's id. Goku's planet_id = 1 means Earth.
NULL"No value" or "unknown". Not 0 and not empty text. Frieza's race is NULL.
Part 1

Read data

SELECT picks the columns, FROM picks the table. End every query with ;.

See everything in a table* means all columns.
SELECT * FROM characters;
See only some columnsPrefer this over * in real code.
SELECT name, power_level FROM characters;
Rename a column in the outputAS changes the label only, not the table.
SELECT name AS fighter, power_level AS power
FROM characters;
Remove duplicatesWhich planets do characters come from?
SELECT DISTINCT planet_id FROM characters;
Part 2

Keep only some rows

WHERE keeps the rows where the condition is true. Text always goes in single quotes.

Compare numbers= <> (not equal) > < >= <=
SELECT name, power_level
FROM characters
WHERE power_level > 3000;
Result · 5 rows
namepower_level
Goku9001
Vegeta8500
Gohan4200
Piccolo3500
Frieza5300
Match text exactly
WHERE name = 'Goku'
Combine conditionsBoth must be true (AND) or either one (OR).
WHERE power_level > 1000 AND planet_id = 1
Match any value in a listShorter than writing many ORs.
WHERE race_id IN (2, 4)
Match a rangeBoth ends included.
WHERE power_level BETWEEN 1000 AND 5000
Match a text pattern% = any number of characters, _ = exactly one. ILIKE ignores upper/lower case.
WHERE name LIKE 'G%'      -- starts with G
WHERE name ILIKE '%an%'   -- contains "an", any case
✗ Returns nothing 
WHERE race_id = NULL

NULL means unknown, so even NULL = NULL isn't true.

✓ Finds Frieza 
WHERE race_id IS NULL

Always use IS NULL or IS NOT NULL.

Part 3

Sort and take the top few

ORDER BY sorts: ASC is smallest first (the default), DESC is biggest first. LIMIT keeps the first N rows.

The 3 strongest charactersSort first, then cut.
SELECT name, power_level
FROM characters
ORDER BY power_level DESC
LIMIT 3;

The full shape of a SELECT

Write the clauses in this order. Only SELECT and FROM are required. The orange number is the order the database actually runs them.

SELECTcolumns to showruns 5th
FROMtable, plus JOINsruns 1st
WHEREkeep matching rowsruns 2nd
GROUP BYbundle rows into groupsruns 3rd
HAVINGkeep matching groupsruns 4th
ORDER BYsort the resultruns 6th
LIMITkeep the first Nruns 7th
WhyWHERE runs before SELECT, so it can't use a name you made with AS. ORDER BY runs after SELECT, so it can.
SELECT name, power_level AS power
FROM characters
WHERE planet_id = 1
ORDER BY power DESC
LIMIT 3;
Part 4

Count, add up, and average

Aggregate functions squash many rows into one number. GROUP BY gives you one number per group instead.

Stats for the whole tableCOUNT(*) rows · SUM total · AVG average · MIN / MAX. NULLs are skipped.
SELECT COUNT(*) AS total,
       MAX(power_level) AS strongest,
       MIN(power_level) AS weakest,
       ROUND(AVG(power_level)) AS average
FROM characters;
Result
totalstrongestweakestaverage
890017504356
One count per groupHow many characters live on each planet?
SELECT planet_id, COUNT(*) AS fighters
FROM characters
GROUP BY planet_id;
Result
planet_idfighters

Filter rows and groupsWHERE filters rows before grouping. HAVING filters groups after.
SELECT planet_id, COUNT(*) AS strong
FROM characters
WHERE power_level > 1000    -- rows
GROUP BY planet_id
HAVING COUNT(*) >= 2;       -- groups
Result
planet_idstrong
13
22
RuleEvery column in SELECT must be in GROUP BY or inside an aggregate like COUNT().
Part 5

Combine tables

A character only stores race_id = 1. A JOIN looks up the matching row in races so you can show "Saiyan" instead. ON says how rows match. c and r are short names for the tables.

JOIN · only rows with a match 
SELECT c.name, r.name AS race
FROM characters c
JOIN races r ON c.race_id = r.id;

Join three tablesTechnique → character → planet. Just chain the JOINs.
SELECT c.name, t.name AS technique, p.name AS planet
FROM techniques t
JOIN characters c ON t.character_id = c.id
JOIN planets p    ON c.planet_id = p.id;
Part 6

A query inside a query

The inner query in parentheses runs first, and its answer is used by the outer one.

Who's stronger than average?The inner query returns 4356.375.
SELECT name, power_level
FROM characters
WHERE power_level >
  (SELECT AVG(power_level) FROM characters);
Result

Part 7

Add, change, and remove rows

These change the table for real. You can always reset to fresh data.

Add a rowList the columns, then the values in the same order. Skip id, it's generated. RETURNING shows what was created.
INSERT INTO characters (name, power_level, planet_id, race_id)
VALUES ('Yamcha', 400, 1, 2)
RETURNING id;
Change rowsSET says what to change, WHERE says which rows.
UPDATE characters
SET power_level = 1200
WHERE name = 'Yamcha';
Remove rows
DELETE FROM characters
WHERE name = 'Yamcha';
CarefulUPDATE or DELETE without WHERE hits every row. DELETE FROM characters; empties the table. Run your WHERE as a SELECT first to see which rows you'd change.
Foreign keysThe database protects you. You can't delete Goku while techniques still point at him, and you can't add a character on planet 99, because it doesn't exist.
Part 8

All or nothing

A transaction groups changes together. Nothing is saved until COMMIT, and ROLLBACK undoes everything since BEGIN.

Delete Goku safelyHis techniques must go first. If either step fails, neither should happen.
BEGIN;
DELETE FROM techniques WHERE character_id = 1;
DELETE FROM characters WHERE id = 1;
ROLLBACK;   -- or COMMIT; to keep it
TipAbout to run something risky by hand? Wrap it in BEGIN; … ROLLBACK;, check the result, then run it again with COMMIT;.
Steps 2 & 3

SQL from code

The same SQL, sent by a Go program instead of typed by you. The values travel separately from the query text.

HTTP request→Go variable→$1 in the query→row in the table
✗ Never glue values in 
"WHERE name = '" + name + "'"

A user could type SQL into name and run it. This is SQL injection.

✓ Use placeholders 
db.Query("... WHERE name = $1", name)

The database fills in $1 safely.

Go callUse it for
db.QueryMany rows. Loop with rows.Next() and copy columns out with rows.Scan(...)
db.QueryRowExactly one row, like a lookup by id or INSERT … RETURNING id
db.ExecNo rows back: UPDATE, DELETE
db.BeginStart a transaction, finish with tx.Commit()

psql and Docker

Commands starting with \ are psql shortcuts, not SQL, so they don't need a ;.

Type thisTo
./connect.shStart the database and open psql
\dtList tables
\d charactersShow a table's columns
\xSwitch to vertical output, for wide rows
qGet out of a long result that's paging
\qQuit psql
docker compose downStop the database (data is kept)
Reset to fresh dataWipes all changes and reloads the starting rows.
docker compose down -v && docker compose up -d --wait
Stuck?If the prompt changes from dragonball=# to dragonball-#, psql is waiting for the rest of your query. You probably forgot the ;. Type ; and press Enter.

When it breaks

Errors you'll probably see

Errors are normal. Read the message: it usually says exactly what's wrong.

The message saysWhat to do
column "goku" does not existPut text in single quotes: 'Goku'
must appear in the GROUP BY clauseAdd that column to GROUP BY, or wrap it in an aggregate
column reference "name" is ambiguousBoth tables have that column. Say which one: c.name
violates foreign key constraintThe id you point at doesn't exist, or other rows still point at this one
aggregate functions are not allowed in WHEREMove conditions on COUNT(), AVG(), … to HAVING
