Anatomía de un SELECT Partes 1–4

Escribí las cláusulas en este orden. El círculo muestra el orden en que la base de datos realmente las ejecuta.

SELECTqué columnas mostrar5
FROMqué tabla (+ JOINs)1
WHEREquedarse con las filas que cumplen2
GROUP BYjuntar filas en grupos3
HAVINGquedarse con los grupos que cumplen4
ORDER BYordenar el resultado6
LIMITquedarse con las primeras N7

Por qué importa: WHERE se ejecuta antes que SELECT, así que no puede usar un alias que hiciste con AS. ORDER BY se ejecuta después, así que sí puede.

SELECT name, power_level AS power
FROM characters
WHERE planet_id = 1
ORDER BY power DESC
LIMIT 3;

La trampa del NULL 2.7

No devuelve nada 
WHERE race_id = NULL
Encuentra a Frieza 
WHERE race_id IS NULL

NULL significa desconocido, así que NULL = NULL no es verdadero. Usá siempre IS NULL / IS NOT NULL. Funciones como AVG ignoran los NULL.

Resumir Parte 4

COUNT(*)cantidad de filas
SUM(col)suma total
AVG(col)promedio (envolvelo en ROUND())
MIN(col) / MAX(col)el menor / el mayor
 
SELECT planet_id, COUNT(*) AS fighters
FROM characters
WHERE power_level > 1000   -- filtra FILAS
GROUP BY planet_id
HAVING COUNT(*) >= 2;      -- filtra GRUPOS
ReglaCada columna del SELECT tiene que estar en el GROUP BY o dentro de una función como COUNT().

JOIN vs LEFT JOIN Parte 5

SELECT c.name, r.name AS race
FROM characters c
LEFT JOIN races r ON c.race_id = r.id;

ON dice cómo coinciden las filas. c y r son nombres cortos (alias) de las tablas.

JOIN: solo las que coinciden
GokuSaiyan
PiccoloNamekian
Frieza—
LEFT JOIN: todas las de la izquierda
GokuSaiyan
PiccoloNamekian
FriezaNULL

Encontrar filas sin pareja: LEFT JOIN y después WHERE derecha.id IS NULL. Así encuentra 5.4 el planeta vacío.

Subconsulta Parte 6

Una consulta adentro de otra. La de adentro se ejecuta primero.

SELECT name, power_level
FROM characters
WHERE power_level >
  (SELECT AVG(power_level) FROM characters);

Cambiar datos Parte 7

INSERT INTO characters (name, power_level, planet_id, race_id)
VALUES ('Yamcha', 400, 1, 2)
RETURNING id;

UPDATE characters
SET power_level = 1200
WHERE name = 'Yamcha';

DELETE FROM characters
WHERE name = 'Yamcha';
⚠Sin WHERE = todas las filas. DELETE FROM characters; vacía la tabla. Probá el WHERE antes con un SELECT para ver qué vas a tocar.

Las claves foráneas dicen que no: no podés borrar a Goku mientras haya técnicas que apuntan a él, ni insertar un personaje en el planeta 99.

Transacciones Parte 8

Todo o nada. No se guarda nada hasta el COMMIT. ROLLBACK deshace todo desde el BEGIN.

BEGIN;
DELETE FROM techniques WHERE character_id = 1;
DELETE FROM characters WHERE id = 1;
ROLLBACK;   -- o COMMIT; para que quede
Tip¿Vas a ejecutar algo riesgoso a mano? Probalo primero adentro de BEGIN … ROLLBACK.
